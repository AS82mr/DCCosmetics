DCCosmetics Documentation

The definitive guide to creating zero-lag, packet-based 3D cosmetics.

1. Overview

The DCCosmetics engine is a highly optimized, packet-based 3D renderer. It creates geometry by manipulating the backgrounds of invisible TextDisplay entities. This means it has zero impact on server block physics and runs incredibly smoothly on the client.

Cosmetics are built by combining multiple primitive 3D "components" (like rings, cylinders, and cones) into a single components list.

2. The Live Sculptor Tool

You don't need to guess coordinates! DCCosmetics comes with a built-in GUI editor and live-reloading mannequin.

Command: /cosmetics sculpt <id>

Spawns a real-time Mannequin (or Citizens NPC, if installed) right in front of you. As you edit the YAML file, the mannequin updates instantly.

  • /cosmetics sculpt editor - Opens the interactive GUI to shift coordinates, add components, and change sizes without leaving the game.
  • /cosmetics sculpt toggle - Toggles the visibility of the underlying mannequin dummy.
  • /cosmetics sculpt clear - Despawns the dummy.

In the GUI Editor, you can Left-Click to add to a value, Right-Click to subtract, and press Q (Drop) to type an exact number in chat!

3. Global Settings

Every cosmetic file (e.g., my_cosmetic.yml) requires these base settings at the top of the file:

id: "my_custom_cosmetic"       # The unique internal ID
type: "head"                   # Slots: head, chest, waist, boots
rarity: "epic"                 # uncommon, rare, epic, legendary
global-offset: [0.0, 2.2, 0.0] # Shifts the ENTIRE cosmetic
head-tracking: true            # (HEAD ONLY) Makes the cosmetic look up/down
display-item: "eyJ0ZX..."      # Base64 string for the GUI Head

animated: true                 # Spins the ENTIRE cosmetic
spin-speed: 4.0                # Speed of global spin
What is head-tracking?

By default, cosmetics lock to the player's Body Yaw (shoulders). If you are building a custom helmet or mask, set head-tracking: true. This allows the geometry to pitch up and down seamlessly when the player looks at the sky or floor!

4. Component Shape Types

Every piece of geometry you add goes under the components: section. Every component needs a type, color, and local-offset.

solid (Flat Planes / Cubes)

Spawns flat 2D planes. If sides > 1, it spawns them in a circle facing outward.

  • length: How long the plane is.
  • width: How wide the plane is.
  • pitch: Up/Down tilt (90.0 lays it flat on the ground).

star (Spiky Stars)

Similar to solid, but alternating sides are shorter, creating perfect multi-pointed stars.

  • length: The size of the primary spikes.
  • short-length: The size of the inner/secondary spikes.

flat_ring (Halos / Discs)

Generates a mathematically perfect horizontal flat ring or disc (like a Saturn ring).

  • radius: How wide the ring is.
  • width: How thick the ring band is.

cylinder (Tubes / Bands)

Generates a vertical tube (perfect for crowns, armbands, or hover-thruster engines).

  • radius: Width of the tube (Player head is 0.25 radius).
  • height: How tall the tube is.

cone (Horns / Spikes / Exhausts)

A cylinder where the walls pitch inward or outward.

  • inward-pitch: The angle. Positive makes a sharp point. Negative flares outward like a crown.

hourglass (Energy Cages / Twisters)

Stacks two cones on top of each other. Great for sci-fi energy fields or tornadoes.

burst (Spherical Explosions)

Uses Fibonacci sphere math to generate a 3D explosion of spikes pointing in all directions.

5. Raw Nodes (Absolute Control)

Don't want to use generated shapes? You can manually place individual panels with absolute control over their Matrix Scale, Translation, and Rotation by placing them under the nodes: section instead of components:.

nodes:
  custom_matrix_piece:
    scale: [1.0, 1.0, 1.0]
    translation: [0.0, 0.5, 0.0]
    rotation: [0.0, 45.0, 0.0] # Pitch, Yaw, Roll
    color: "#FF00FF"

6. Animations

Instead of spinning the whole cosmetic, you can animate individual components.

components:
  my_floating_gem:
    type: "solid"
    color: "#00FFFF"
    animated: true
    animation-type: "float"    # spin, float, glitch
    animation-speed: 4.0
  • spin: Rotates the component locally.
  • float: Bobs up and down using a sine-wave.
  • glitch: Rapidly teleports to simulate cyberpunk holograms.

7. Inverse Kinematics (Walk & Wing Engines)

DCCosmetics contains native inverse kinematic tracking engines. By simply naming your components properly, the engine will automatically attach physics-based animations to them!

The Walk Engine (Boots Only)

Tracks player distance to simulate vanilla leg swinging. Prefix components with left_ or right_.

components:
  left_boot_ring:  # Engine detects "left_" and binds to the Left Leg
    type: "flat_ring"
    local-offset: [-0.13, 0.0, 0.0]
    
  right_boot_ring: # Engine detects "right_" and binds to the Right Leg
    type: "flat_ring"

The Wing Engine (Chest Only)

Reads player state (Jumping, Falling, Sprinting, Idle) to dynamically control wing-flapping speed and intensity. Prefix components with wing_left_ or wing_right_.

components:
  wing_left_main:  # Binds to the procedural Left Wing kinematic bone!
    type: "solid"

8. The Footstep Engine (Boots Only)

Automatically drops holographic footprints mapped to the walk cycle!

footstep:
  particle: "end_rod"
  color: "#FFD700"
  sound: "entity.strider.step"
  volume: 0.5
  pitch: 1.5
Hologram Shapes

The engine reads the id of your cosmetic file to determine what footprint to drop! Contains "star" (★), "heart" (❤), "ring" (⬤), Default (█).
